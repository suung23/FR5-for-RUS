# safety_estop — 비상정지·보호정지·복귀

세 수준의 정지를 **분리해서** 구현한다. 한 이름으로 부르면, 소프트웨어가 살아
있어야만 작동하는 보호를 비상정지라고 믿게 되고, 그 믿음이 정확히 진짜 비상정지를
두지 않는 이유가 된다.

| 수준 | 누가 거는가 | 무엇을 지나는가 | 이 저장소의 구현 |
|---|---|---|---|
| **1. 정상 Stop** | 조작자 | GUI → 브리지 → 제어 노드 | 기존 정책/프로빙 정지 버튼 |
| **2. 보호정지** | 자동 판정 | 센서 → 이 노드 → 운동 금지 | `estop_cmd` 없이 `trip.py` 가 건다 |
| **3. 비상정지** | 사람, 물리 버튼 | **아무 소프트웨어도 지나지 않는다** | §1 의 배선. 이 패키지는 **관측만** |

> ⚠️ **지금 이 저장소의 상태.** `config/estop.yaml` 의 `hardware.present` 기본값은
> `false` 다. 즉 **물리 비상정지 회로가 아직 없다.** 이 패키지가 거는 것은 전부
> 수준 2(보호정지)이고, 그것은 전원·ROS·이 노드·F/T 센서가 모두 살아 있어야
> 작동한다. 사람이나 환자 앞에서 쓸 구성이 아니다. §1 을 시공하고 플래그를
> `true` 로 바꾸기 전까지, 화면의 "ESTOP" 이라는 단어는 수준 2 를 뜻한다.

## §1. 물리 비상정지 루프 (수준 3)

ISO 13850 이 다루는 것이 이 회로다. 설계 원칙 네 가지와, 그것이 이 배선의 어디에
대응하는지:

1. **래칭(latching).** 누르면 눌린 채로 잠긴다. 손을 떼도 풀리지 않는다.
2. **직접 개로(positive opening).** 접점이 기계적으로 강제로 열린다. 스프링이나
   전자적 판단에 기대지 않는다.
3. **리셋이 재기동이 아니다.** 버튼을 돌려 뽑아도 로봇은 움직이지 않는다. 별도의
   의도적인 조작이 한 번 더 있어야 한다.
4. **소프트웨어 독립.** GUI·ROS·네트워크·이 노드 중 무엇이 죽어도 작동한다.

### 배선

```
  ┌──────────────────────┐
  │ 래칭형 버섯머리 버튼  │   2채널 NC 접점 (직접 개로형)
  │  (조작자 손 닿는 곳)  │   ── ch0 ──┐
  └──────────────────────┘   ── ch1 ──┤
                                      │
                             ┌────────▼─────────────────────┐
                             │ FR5 컨트롤러 안전입력         │
                             │  SI0 / SI1 (이중화)           │
                             │  → 내부 안전회로가 구동 차단  │
                             └────────┬─────────────────────┘
                                      │ (읽기 전용)
                             ┌────────▼─────────────────────┐
                             │ us_servo_node                │
                             │  GetRobotEmergencyStopState  │
                             │  safety_stop0/1_state        │
                             │  → /fr5_right/safety/hardware│
                             └────────┬─────────────────────┘
                                      │
                             safety_estop_node → 콘솔
```

굵은 선(버튼 → 컨트롤러)은 **전선이다.** 소프트웨어가 그 경로에 끼어들 자리가
없다. 가는 선(컨트롤러 → 노드 → 콘솔)은 **관측**이고, 이 경로가 통째로 죽어도
로봇은 멈춘 채로 있다. 반대로 이 경로만 살아 있고 전선이 끊겨 있으면 아무것도
멈추지 않는다 — 그래서 §4 의 점검이 전선 쪽을 본다.

### 왜 2채널인가

한쪽 접점이 붙어 버리는 고장(용착)은 눈에 안 보이고, 그 상태의 버튼은 **다음번에
안 멈춘다.** 두 채널이 서로 다른 말을 하면 그 자체가 고장 신호이므로,
`hardware.py` 는 불일치를 **눌린 것과 같이 취급하되 사유를 다르게** 말한다.

### 리셋 절차 (원칙 3)

1. 위험 원인을 제거한다.
2. 버튼을 돌려 뽑는다 → 회로가 닫힌다. **로봇은 여전히 움직이지 않는다.**
3. 컨트롤러 측 안전 리셋.
4. 콘솔에서 `RESET` → 단계가 `DISARMED` 로 간다. **감시는 켜지지 않는다.**
5. 다시 쓰려면 `ARM` 을 한 번 더 누른다.

4 와 5 를 나눈 것이 원칙 3 이다. 리셋 한 번으로 감시까지 켜지면, "지우기" 와
"다시 시작" 이 같은 버튼이 된다.

## §2. 보호정지 (수준 2) — 이 패키지가 자동으로 거는 것

조작자가 콘솔에서 고치는 문턱은 **둘**이다.

| 조건 | 기본값 | 어디서 |
|---|---|---|
| 접촉력 `‖F‖` 가 문턱을 `force_confirm_s` 동안 넘음 | 8.0 N | 콘솔 / `estop.yaml` |
| 확인창 없이 즉시 거는 값 | 15.0 N | 콘솔 / `estop.yaml` |
| 어느 관절이든 가동범위의 90 % 도달 | 0.90 | 콘솔 / `estop.yaml` |
| 힘 또는 관절 표본이 `stale_s` 보다 오래됨 | 0.25 s | `estop.yaml` |
| 물리 회로 관측 (수준 3) | — | 읽기 전용 |

**`probe.yaml` 의 5 N 과 겹치지 않는다.** 그쪽은 "너무 세게 눌렀으니 빼라" 이고
(조절기가 프로빙을 계속하며 후퇴한다), 여기 8 N 은 "제어가 그것을 못 했다" 이다.
후자는 래치되고 세션이 끝난다. 두 층의 간격 3 N 은 팬텀 기준이며, 조직으로 갈 때
`probe.yaml` §2.1 의 7 N 과 함께 다시 정해야 한다.

### 관절 여유를 세는 법

`|q| ≥ 0.9 × upper` 로 읽으면 FR5 의 비대칭 축에서 뜻이 무너진다 — J2 는
`[-265°, +85°]` 라 `0.9 × 85 = 76.5°` 가 하한 쪽에는 아무 의미가 없다. 그래서
**가동범위 중앙에서 한계까지 몇 %를 썼는가** 로 센다:

```
reach = |q - center| / half,    center = (lo+hi)/2,  half = (hi-lo)/2
```

J2 라면 중앙 −90°, 반폭 175° 이므로 `+67.5°` 와 `−247.5°` 가 둘 다 90 % 다.
콘솔에는 비율과 **남은 각도**를 함께 띄운다 — 비율은 비교용, 각도는 판단용이다.

### 힘을 믿을 수 없을 때는 후퇴하지 않는다

센서가 끊기거나 NaN 이면 정지는 걸되 **자동 복귀를 허용하지 않는다**
(`trip.py` 의 `_RELEASE_ALLOWED`). 후퇴도 운동이고, 그 운동이 멈출 조건을 바로 그
못 믿을 힘이 쥐고 있기 때문이다. 이것은 임의의 선택이 아니라 위험분석이 돌려줘야
하는 답이며, 그때까지의 기본값을 "서고 사람을 부른다" 로 둔 것이다.

## §3. 복귀 — 선 자리에서 끝내지 않는다

정지는 멈추는 것으로 끝나지 않고 **초기 자세로 돌아간다.** 다만 그 복귀는
자동으로 시작되지 않는다.

```
DISARMED ──ARM──▶ ARMED ──(판정/물리회로)──▶ TRIPPED
                    ▲                            │
                    │                        RECOVER (조작자가 길게 누름)
                 RESET                            │
                    │                             ▼
                  SAFE ◀──경로 소진──  RELEASING ──▶ RETURNING
                                              (힘이 떨어지면)
```

자동으로 일어나는 전이는 `ARMED → TRIPPED` **하나뿐이다.**

* `TRIPPED` 에서 스스로 복귀하지 않는다. 걸린 이유를 사람이 읽기 전에 로봇이
  움직이면, 그 움직임이 원인을 덮는다.
* 복귀가 끝나도 `SAFE` 에서 멈춘다. **운동 금지는 풀리지 않는다.**
* `RESET` 은 `DISARMED` 로 간다 (§1 의 원칙 3).
* 프로세스가 죽었다 살아나면 `DISARMED` 에서 시작한다. 이전 단계를 디스크에 남겨
  이어받지 않는다 — "전원 복구 뒤 이전 명령이 재개되지 않는다" 가 이 한 줄이다.

### 왜 MoveJ 가 아닌가

홈으로의 `MoveJ` 는 지금 자세와 홈을 잇는 **관절공간 직선**을 간다. 그 직선이
지나는 카테시안 경로는 아무도 본 적이 없고, 그 선의 출발점은 복부를 향해 기울어진
프로브다. 가장 위험한 순간에 가장 검증되지 않은 경로를 쓰게 된다.

대신 `ARM` 한 순간부터 지나온 관절 자세를 1° 간격으로 남기고(`PathRecorder`),
복귀는 그것을 **역순으로 되밟는다**. 두 가지가 따라온다:

1. 이미 한 번 지나온 경로다. **정적인** 주변물에는 새로 부딪힐 데가 없다.
   ⚠️ 움직이는 것에는 아니다 — 사람과 침대는 그 사이에 움직인다. 그래서 복귀
   중에도 감시가 계속 돌고, 힘이 다시 오르면 복귀를 **중단**한다.
2. 되밟기의 첫 구간이 곧 접촉 해제다. 후퇴 방향을 따로 계산할 필요가 없다.

속도는 두 단계다 — 접촉이 남아 있는 동안 2 °/s, 떨어진 뒤 8 °/s. 복귀 지령도
`us_servo_node` 의 `JointCommandLimiter` 를 통과하므로 속도·가속도·관절한계·
추종오차 밴드가 거기서 다시 걸린다.

### 보장하지 않는 것

* **빵부스러기는 유한하다** (기본 2000 점). 넘치면 가장 오래된 것부터 버리고,
  그때의 "초기 자세" 는 남아 있는 가장 오래된 점이다. 콘솔이 그 사실을 표시한다.
* **되밟기는 충돌 회피가 아니다.** 환경이 변하지 않았다는 가정 위에 서 있다.

## §4. 운용

```bash
# 설정을 주고 띄운다 (제어 스택과 같은 네임스페이스)
ros2 run safety_estop safety_estop --ros-args \
  --params-file install/safety_estop/share/safety_estop/config/estop.yaml

# 콘솔 없이 손으로 거는 법 (고장 시험용)
ros2 topic pub -1 /fr5_right/safety/estop_cmd std_msgs/String \
  '{data: "{\"command\":\"arm\"}"}'
ros2 topic echo /fr5_right/safety/estop_state
```

### 세션 전 점검 (전선 쪽)

1. `estop_state` 의 `hardware.present` 가 `true` 인가. `false` 면 **비상정지가
   없는 구성**이다.
2. 버튼을 실제로 누른다. 콘솔 단계가 `TRIPPED`, 사유가 `hardware` 로 바뀌는가.
3. 채널 불일치 경고가 뜨지 않는가 (용착 점검).
4. 돌려 뽑는다. 로봇이 **스스로 움직이지 않는가** (§1 원칙 3).

### 아직 하지 않은 것

* **고장 주입 시험.** 센서 단절·통신 지연·명령 폭주·힘 초과·전원 복구를 넣고
  정지까지의 **시간·이동거리·최대 힘**을 재는 일. `config/estop.yaml` 의 값은
  그 측정 전의 설계값이다.
* **두 파일의 관절 한계 일치 검사.** `estop.yaml` 과 `probe.yaml` 이 각자 사본을
  들고 있고, 어긋나도 아무도 거부하지 않는다.
* **영상 신선도 감시.** 위험 표의 "초음파 영상이 멈춤" 은 아직 이 노드가 보지
  않는다 (다음 수준).
* **사용성 평가.** 모의 환경에서 조작자가 `STOP`·보호정지·비상정지를 구별하고
  실제로 찾아 쓸 수 있는지 (IEC 62366-1).

표준 참조는 설계 근거이지 적합성 주장이 아니다. 이 저장소는 연구용이며, 임상
사용이나 임상시험에는 별도의 품목 분류·허가 검토가 선행되어야 한다.
