## 이 문서가 답하는 것

초음파 영상기반 제어를 설계하려면 먼저 하나를 정해야 합니다: **프로브를 움직였을 때 영상이 어떻게 변하는가.**

그 답이 여섯 자유도에 대해 균일하지 않습니다. 셋은 정확하고 상수인 관계를 갖고, 셋은 영상 밖의 3D 형상에 의존합니다. 이 갈라짐이 어디서 오는지가 이 문서의 내용이며, 결론은 한 줄입니다:

> **영상면을 자기 자신으로 보내는 운동은 셋뿐이고, 그 셋만 군(group)을 이룹니다.**

읽는 순서: §1 프레임 → §2 픽셀 → §3 여섯 자유도 → §4 SE(2) → §5 나머지 셋.

## 1. 프레임 설정 — 영상면은 프로브에 붙어 있다 ✅

![프로브 프레임과 영상면](figures/10-probe-frames.svg)

*그림 1. 프로브 프레임과 B-mode 영상면. 옅은 점선 두 장은 유한한 슬라이스 두께.*

프로브 프레임의 원점은 **접촉면 중심**입니다. 세 축은 트랜스듀서의 물리적 구조에서 바로 나옵니다.

| 축 | 정의 | 소노그래퍼 용어 |
|---|---|---|
| `+x` | 트랜스듀서 배열이 늘어선 방향 | lateral |
| `+y` | 배열에 수직, 영상면 밖 | elevational (슬라이스 두께) |
| `+z` | 빔이 조직으로 들어가는 방향 | depth / axial |

여기서 이 문서 전체의 전제가 나옵니다:

```
영상면  Π  =  { y_probe = 0 }        (probe 프레임의 x–z 평면)
```

**`Π`는 공간에 고정된 것이 아니라 프로브에 강체로 붙어 있습니다.** 프로브가 움직이면 평면도 함께 움직입니다. 이것이 카메라와 다른 점의 출발입니다 — 카메라는 3D를 2D로 *투영*하지만 프로브는 3D를 2D로 *절단*하고, 그 절단면이 손에 들려 있습니다.

⏳ **원점의 실제 위치는 CAD 대기입니다.** DESIGN_NOTES §4.2의 툴 변환이 이 점을 결정하며, §4.5가 지적한 대로 접촉면에서 `δ`만큼 어긋나면 회전 지령이 `v_slip = ω × δ`의 미끄러짐을 만듭니다.

### 슬라이스 두께 — 영상은 평면이 아니다 🟡

그림 1의 옅은 점선 두 장이 이것입니다. B-mode 영상은 수학적 평면의 단면이 아니라 **두께 🟡 2–5 mm짜리 얇은 판을 elevational 방향으로 적분한 것**입니다.

이 사실이 두 번 쓰입니다:
- §3의 면외 운동이 "영상을 갑자기 바꾸지 않고 서서히 흐리게" 만드는 이유
- `IMAGE_SERVOING_MATH.md` §8의 스페클 비상관이 측정하는 대상 — 상관 길이 `σ_e ≈` 빔폭/2

## 2. 영상면과 픽셀 좌표 — 미지 깊이가 없다 ✅

![영상면과 픽셀 좌표의 대응](figures/11-image-pixels.svg)

*그림 2. 픽셀 좌표의 두 원점. 상호작용 행렬이 요구하는 것은 배열 중심의 투영입니다.*

평면 안의 점 `(x, 0, z)`는 픽셀 `(u, v)`와 **상수 배율 하나**로 이어집니다:

```
x = s · u          s [mm/px]
z = s · v
```

카메라라면 여기에 미지의 깊이 `Z`가 들어가 상호작용 행렬을 오염시킵니다 (`L_p = [−1/Z, 0, u/Z; …]`). 초음파의 `s`는 **음속 1540 m/s와 스캔 기하로 결정되는 알려진 상수**입니다.

> **초음파는 계량(metric) 모달리티입니다.** 이것이 면내 축을 학습 없이 해석적으로 풀 수 있는 근거이며, `IMAGE_SERVOING_MATH.md` 정리 2입니다.

### ⚠️ 원점을 혼동하면 회전 항이 틀립니다

`ControlState`의 `COORDINATE_CONVENTION`은 원점을 **좌상단**에 둡니다. 그런데 상호작용 행렬 (4.3)이 요구하는 원점은 **프로브 원점의 영상면 투영 = 배열 중심**입니다. 둘은 `(u₀, v₀)`만큼 떨어져 있습니다:

```
u = u_topleft − u₀
v = v_topleft − v₀
```

⏳ **`(s, u₀, v₀)` 확정이 검증 계획 1번입니다.** `configs/*.yaml`의 `pixel_spacing: 1.0`은 현재 placeholder입니다. 이 값을 틀리면 병진 항은 배율만 어긋나지만 **회전 항 `−ω_y·v`는 통째로 틀립니다** — `v`가 원점 의존이기 때문입니다.

## 3. 여섯 자유도 — 평면을 지키는 셋, 떠나는 셋 ✅

프로브를 움직이는 방법은 여섯 가지입니다. 각각에 대해 물을 것은 하나입니다:

> **영상면 `Π`가 공간에서 같은 평면으로 남는가?**

![여섯 자유도의 면내/면외 분류](figures/12-dof-inplane-outplane.svg)

*그림 3. 점선은 원래 평면, 실선은 운동 후. 윗줄은 둘이 겹칩니다.*

남는다면 잘리는 해부구조가 그대로이고, 영상은 **같은 단면이 재프레이밍**된 것뿐입니다. 떠난다면 **다른 조직**을 보게 되고, 무엇이 얼마나 달라지는지는 영상 밖의 3D 형상에 달립니다.

| 축 | 분류 | 소노그래퍼 동작 | 영상에서 보이는 것 | 제어원 (DESIGN_NOTES §5) |
|---|---|---|---|---|
| `v_x` | **면내** | 측방 슬라이딩 | 내용이 반대로 평행이동. 이득 정확히 `−1/s` | 영상 policy |
| `v_z` | **면내** | 압입 / 깊이 | 내용이 세로로 평행이동 | admittance (`F_n → F_n*`) |
| `ω_y` | **면내** | 힐-토 로킹 | 내용이 면 안에서 회전. `θ̇ = ω_y` | 아날리틱 (`M_y → 0`) |
| `v_y` | **면외** | elevational 슬라이딩 | 다른 슬라이스. 변화량 `∝ ∮κ dl` | 영상 policy |
| `ω_x` | **면외** | 팬 / 틸트 | 평면이 부채질하듯 쓸림 | 아날리틱 (`M_x → 0`) |
| `ω_z` | **면외** | 프로브 회전 | 빔축 둘레 피벗. 변화량 `∝ ∮κx dl` | 영상 policy |

`κ`는 조직 표면 법선이 영상면에서 기울어진 정도(`= tan θ_out`)이며, **면외 관측성 전체를 게이팅합니다.** 정의와 결과는 `IMAGE_SERVOING_MATH.md` §3–§5.

### ⚠️ 여기가 설계의 쟁점

영상 관측성이 완벽한 두 축(`v_z`, `ω_y`)은 힘 루프로 갔고, 영상 policy는 **면내 하나 + 면외 둘**을 받았습니다.

```
영상 policy  ←──  v_x (면내)  +  v_y, ω_z (면외)
힘 루프      ←──  v_z, ω_y (면내)  +  ω_x (면외)
```

이 배분 자체는 DESIGN_NOTES §5.1의 논거로 **정당합니다** — 자세 정렬은 모멘트가 모호함 없이 측정하고, 영상으로 배우기 특히 어려운 축이니까요. 수학이 그 결정을 지지합니다 (`ω_x`는 면외 축입니다).

다만 **"policy가 맡은 3축이 비슷한 난이도"라는 암묵적 전제는 성립하지 않습니다.** 세 축은 서로 다른 수학적 문제입니다:

```
v_x  : 면내. 1차 오차 회귀. 해석적. 학습 불필요           ✅
v_y  : 면외. 2차 극값탐색. 목표에서 이득 소멸             ⚠️
ω_z  : 면외. 2차 극값탐색. 오정렬에 비례하는 1차 항       🟡
```

### 용어 주의 🟡

DESIGN_NOTES §5.3의 "면내 축 (x, y, rz)"에서 "면내"는 **피부면 내**를 뜻하는 것으로 읽힙니다 (§4.1의 "x, y 병진 = 피부 위 슬라이딩"과 일관). 이 문서의 "면내"는 **영상면 내**입니다. 두 용법이 겹치므로 논문·코드 주석에서는 구분해 쓰십시오. 설계 오류는 아닙니다.

## 4. SE(2)의 정의 — 평면을 지키는 운동들이 이루는 군 ✅

"평면을 지키는 셋"은 임의로 고른 묶음이 아닙니다. **안정자 부분군**(stabilizer subgroup)이라는 정확한 대수적 대상입니다:

```
Stab(Π)  =  { g ∈ SE(3)  :  g·Π = Π }
```

![SE(2) 안정자 부분군의 행렬 형태](figures/13-se2-stabilizer.svg)

*그림 4. `g·Π = Π`의 대수적 내용 — `y` 행과 열이 항등으로 얼어붙습니다.*

프로브 좌표의 4×4 동차행렬로 풀면 구조가 즉시 드러납니다:

```
      ⎡ cos θ    0    sin θ  │  t_x ⎤   ← x
g  =  ⎢   0      1      0    │   0  ⎥   ← y   (항등으로 고정)
      ⎢ −sin θ   0    cos θ  │  t_z ⎥   ← z
      ⎣   0      0      0    │   1  ⎦
            ↑      ↑      ↑      ↑
            x      y      z      t
                 (고정)
```

**`y`에 해당하는 행과 열이 통째로 항등입니다.** 남는 자유 성분은 셋 — 회전 `θ` 하나와 병진 `t_x`·`t_z` 둘. 이것이 정확히 SE(2)이며, "영상면 위에 유도되는 SE(2)"라는 말의 내용입니다.

무한소로 보면 생성원 셋이 그대로 나옵니다:

```
𝔰𝔱𝔞𝔟(Π) = span{  ∂/∂x ,   ∂/∂z ,   x ∂/∂z − z ∂/∂x  }
                   v_x       v_z            ω_y
```

### 왜 이것이 제어에 중요한가 ✅

세 번째 생성원이 만드는 평면 속도장이

```
w_ip  =  ( − v_x − ω_y z ,  − v_z + ω_y x )
```

이고, 이 장은 **표면 법선 `n`을 전혀 포함하지 않습니다.** 그래서 영상 모멘트를 미분하고 발산정리로 되돌리면 미지 형상이 소거되고, centroid 상호작용 행렬이 **정확하고 상수인** 형태로 떨어집니다:

```
⎡u̇_g⎤   ⎡ −1/s     0     −v_g ⎤ ⎡ v_x ⎤
⎢   ⎥ = ⎢                      ⎥ ⎢ v_z ⎥
⎣v̇_g⎦   ⎣   0    −1/s     u_g ⎦ ⎣ ω_y ⎦
```

미지수가 없습니다. `v_x` 축은 이것만으로 비례제어가 성립하며 **학습이 필요 없습니다.**

## 5. 나머지 셋은 군이 아니다 ⚠️

대칭성 때문에 면외 셋도 부분군일 것 같지만 아닙니다. `Stab(Π)`는 진짜 부분군입니다 — 평면을 지키는 두 운동을 이어 붙이면 여전히 지킵니다. 면외 셋은 **여집합일 뿐 닫혀 있지 않습니다.**

![면외 생성원의 교환자는 면내 롤이 된다](figures/14-commutator.svg)

*그림 5. 두 경로는 같은 평면에서 끝나지만 내용의 롤이 다릅니다.*

```
[ ω_x , ω_z ]  =  − ω_y  ∈  𝔰𝔱𝔞𝔟(Π)
```

**면외 생성원 둘의 괄호가 면내로 떨어집니다.** 팬(`ω_x`)과 프로브 회전(`ω_z`)을 순서만 바꿔 실행하면 결과가 다르고, 그 차이가 영상면 내 롤입니다.

### ⚠️ 실제 함의 — 이 설계에서 실제로 일어납니다

힘 루프가 `ω_x`를, policy가 `ω_z`를 **동시에** 움직입니다. 두 축이 함께 돌면 지령하지 않은 영상 롤이 생깁니다.

다행히 `ω_y`도 힘 루프가 쥐고 있어 자세 정렬이 그것을 되돌립니다. 문제는 **policy 입장에서 자기가 낸 `ω_z`가 영상 롤로 새는 것으로 보인다**는 점입니다 — 자기 행동과 영상 변화의 대응이 깨집니다.

🟡 **처방:** `IMAGE_SERVOING_MATH.md` §7(c)의 policy 입력 정상화에서, (7.2)로 워핑해 제거할 대상에 **`ω_x`·`ω_z` 교차항이 만드는 `ω_y` 성분을 포함**시키십시오. 지령 twist를 알고 있으므로 예측 가능하고, 연산량은 추가되지 않습니다.

### 정리

이 비대칭 — **면내는 대수적으로 닫힌 구조를 갖고 면외는 갖지 못한다** — 가 두 블록의 제어 난이도가 갈라지는 뿌리입니다. 우연이 아닙니다.
