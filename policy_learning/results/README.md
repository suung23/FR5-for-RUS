## 1. 팬텀이 ep0020 기점으로 움직였다

`main_rule/episodes.csv` 의 `area_max` 가 ep0019 까지 0.11–0.14, ep0020 부터 0.03–0.08 이다.
조작자 확인: **ep0020 기점으로 팬텀 위치가 바뀌었다.** 기록된 자세 좌표가 팬텀의 다른 자리를
가리키게 되므로 **위치 A(ep1–19)와 위치 B(ep20–)의 자세는 짝이 되지 않는다.**

→ 분석에 쓸 수 있는 것은 **ep0001–0019**, 즉 자세 1–6 의 `rule`·`hold`·`search` 다.
ep0020·0021 (자세 7) 과 ep0025–0028 (policy·hybrid) 은 **옛 좌표로 복귀한 것이라 제외**한다.

## 2. 위치 B 에서 규칙 제어기가 유지 국면에 들어가지 못했다

`episodes.csv` 의 `hold` 열이 위치 B 에피소드에서 전부 0 이다. 원인 둘:

* `RuleController.max_excursion_deg = 24°` (CLI 플래그 없음). 찾기축 `thx,thy,y` 를 ±12° 로
  훑으면 다 끝내기 전에 24° 를 넘어 `복귀` 로 빠지고, 복귀가 끝나면 다시 `찾기` 로 돌아간다.
  실측 이탈 최대 26.0°.
* `q_good_enough = 0.85` 가 위치 B 에서 도달 불가능했다 (`q_view` 천장 0.839). 면적이
  `AREA_FULL`(0.12) 의 68 % 까지만 가기 때문이다. 0.70 으로 내렸으나(사전 등록) 위 이탈
  문제가 남아 해결되지 않았다.

`hybrid`(찾기=규칙 · 정렬=정책)는 유지 국면에서만 정책으로 넘어가므로, 유지가 0 틱이면
`rule` 과 동작이 같다 — 그 비교는 성립하지 않는다.
